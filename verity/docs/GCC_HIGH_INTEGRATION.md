# Verity — Microsoft Entra ID GCC High Integration

**Status: not implemented.** This document describes what exists today (a
correctly-defaulted configuration surface and a mock connector catalog
entry), what section 5 of the original build directive calls for, and what
remains to build it for real. Nothing on this page should be read as a
working integration.

## 1. Why this exists as its own document

GCC High is called out as "a mandatory foundational capability" in the
directive this build is based on, and several files in this codebase
(`app/Support/Auth.php`, `app/Support/Connectors.php`, `app/Http/AuthController.php`,
`app/Http/ApiRouter.php`) point here in their doc comments. This file exists
so those references resolve to something true, not to a 404.

## 2. What is actually implemented

- **Correct endpoint defaults.** `app/Support/Config.php` defaults
  `GRAPH_BASE_URL` to `https://graph.microsoft.us`, `ENTRA_AUTHORITY_HOST` to
  `https://login.microsoftonline.us`, and `AZURE_PORTAL_URL` to
  `https://portal.azure.us` — the **US Government cloud** endpoints, never
  the commercial `graph.microsoft.com` / `login.microsoftonline.com`. This is
  the one piece of the directive's GCC High requirement that is genuinely
  satisfied today: if a real integration is built later, it starts from the
  correct hosts by default rather than needing a late fix.
- **`Config::entraConfigured()`** reports whether all four `ENTRA_TENANT_ID` /
  `ENTRA_CLIENT_ID` / `ENTRA_CLIENT_SECRET` / `ENTRA_REDIRECT_URI` variables
  are set. Nothing in the app currently calls this to drive a real sign-in
  flow — it is read, not acted on.
- **`GET /auth/sso`** (`AuthController::ssoUnavailable()`) returns an honest
  **HTTP 503** with an explanation, rather than a broken or fake sign-in
  button. Local email/password at `/auth/login` is the only working
  authentication path.
- **A mock connector catalog entry** (`connector_type = 'entra_gcc_high_mock'`
  in `app/Support/Connectors.php`) exists in the Application Catalog and is
  what the synthetic seed data uses for the "Microsoft Entra ID (GCC High)"
  application. Its capability manifest (`Connectors::defaultManifest()`)
  honestly claims only `discover_accounts`, `discover_roles`,
  `discover_groups`, `read_account_status`, and `read_entitlement_assignments`
  — never `provision_access`, `modify_access`, `revoke_access`, or
  `disable_accounts`. **No code anywhere in this repository makes a real
  call to `graph.microsoft.us` or any other Microsoft endpoint.** All
  "Entra" data in the system is synthetic, generated by `database/seed.php`.

## 3. What a real integration would require (not started)

1. **App registration in the GCC High tenant** — a technical owner creates an
   Entra ID application registration *in the organization's actual GCC High
   tenant* (not commercial Azure AD), with the minimum Graph permissions
   needed (read-only directory/group/role-assignment scopes to start —
   provisioning scopes only if/when write-back is built and approved).
2. **Authentication method** — prefer certificate-based service-principal
   credentials or managed/workload identity over a client secret, consistent
   with least-privilege guidance in `docs/SECURITY.md`. A client secret
   would go in `ENTRA_CLIENT_SECRET`, sourced from a secrets manager — never
   committed, never logged.
3. **A real connector implementation** — an HTTP client against
   `https://graph.microsoft.us/v1.0/...` using the GCC High authority
   (`https://login.microsoftonline.us`) for token acquisition, with
   pagination, throttling/retry handling, and incremental sync checkpoints.
   None of this exists yet; `Connectors.php` today is configuration/catalog
   metadata only.
4. **A sync execution engine** — something has to actually call the connector
   on a schedule or on demand, write `connector_sync_job` rows, create/update
   `system_account` and `entitlement_assignment` rows from the response, and
   surface failures. The `connector_sync_job` table exists in the schema;
   nothing writes to it outside the seed script's static rows.
5. **A sign-in flow** — an OIDC authorization-code flow against the GCC High
   authority, ID token validation, and a mapping from the Entra identity to
   an `app_user` row. `Config::entraConfigured()` is the only piece of this
   that exists.
6. **Development safety** — before any of the above touches a real tenant,
   build and test against the mock connector only. Do not point this build
   at a production GCC High tenant without separate, explicit organizational
   authorization (per section 26 of the original directive).

## 4. Verification status

Nothing in this document has been tested against a real Microsoft Graph GCC
High endpoint — there is no tenant, app registration, or credential
available in this development environment. "Verified" above means verified
by reading the source code that implements it, not by a live API call.
